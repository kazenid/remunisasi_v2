# Implementation Plan — Penilaian UI/UX, upload-toast fix, dan rename TUKIMAN

Laravel 13 + Inertia + Vue 3 + PrimeVue (Sakai/Aura) + Tailwind v4. Kerjakan di mainline (tanpa worktree). Bahasa UI: Indonesia. Patuhi konvensi Sakai/PrimeVue (komponen global, grid 12 kolom, `.card`, token surface/text, dark mode).

## Temuan hasil investigasi (dasar keputusan)

- **Diskriminator lampiran selfie vs dokumen (DIKONFIRMASI):** kolom enum `tipe` pada `task_attachments`, konstanta di `app/Models/TaskAttachment.php` → `TaskAttachment::TIPE_FOTO_SELFIE = 'foto_selfie'` dan `TIPE_DOKUMEN = 'dokumen'`. Model juga sudah meng-`append` tiga atribut turunan: `url` (= `route('bukti.show', id)`), `is_image` (`str_starts_with(mime, 'image/')`), dan `ukuran_label`. UI harus bercabang pada `att.tipe === 'foto_selfie'` (bukti selfie) vs selainnya (dokumen). Gunakan `att.is_image` hanya bila ingin aman terhadap dokumen bertipe gambar; untuk tampilan "selfie sebagai foto" pakai `tipe === 'foto_selfie'`.
- **Serialisasi lampiran di penilaian (DIKONFIRMASI):** `app/Http/Controllers/Kabid/ReviewController.php` method `show()` hanya mengirim `id`, `tipe`, `nama_asli` per attachment — TIDAK ada `url`/`is_image`/`mime`. Jadi `ReviewDetail.vue` saat ini tidak punya sumber gambar untuk ditampilkan; serializer harus ditambah `url` dan `is_image` (dan `mime` bila perlu). URL aman disajikan via `route('bukti.show', att.id)` → `AttachmentController@show` (streamed, terotorisasi lewat policy `view`). Rute: `routes/web.php` baris 62 `GET /bukti/{attachment}` name `bukti.show`.
- **Bukti pada ReviewDetail saat ini (DIKONFIRMASI):** `resources/js/Pages/Kabid/ReviewDetail.vue` menampilkan SEMUA lampiran sebagai daftar `<a target="_blank">` dengan ikon (lihat blok `<ul v-if="tugas.attachments.length">` ~baris 112–121). Ini yang diubah: selfie → foto berframe + modal; dokumen → tetap link new-tab.
- **Preview selfie di create-task (DIKONFIRMASI):** `resources/js/Components/form/SelfieCapture.vue` meng-emit objek `File` lewat event `captured`; `resources/js/Pages/Katimker/TaskForm.vue` menampung di `selfieBaru` (ref array) dan hanya merender nama file sebagai `<Chip>` (~baris 240–242). Belum ada thumbnail. Preview dibuat dari `URL.createObjectURL(file)` (ingat `revokeObjectURL` saat hapus/unmount).
- **Bug toast upload gagal (ROOT CAUSE DIKONFIRMASI):** `resources/js/Pages/Katimker/TaskList.vue` menggerakkan toast lewat `watch(() => page.props.flash?.error, ...)`. Dua kegagalan beruntun dengan STRING pesan identik → nilai yang di-watch tidak berubah → watcher tidak fire → toast kedua hilang. Flash dibagikan di `app/Http/Middleware/HandleInertiaRequests.php` method `share()` key `flash` (`success`/`error`/`warning`/`info`). TaskForm.vue tidak terkena bug ini karena memakai callback `onError` submit (bukan watcher flash). Catatan: pengajuan gagal mengembalikan `back()->with('error', ...)` (redirect 302→200 yang dianggap "sukses" oleh Inertia), sehingga pola single-toast lewat flash harus dipertahankan.
- **Bug theme selector di Login (ROOT CAUSE DIKOREKSI setelah review iterasi 1 — lihat catatan di bawah):** Login (`resources/js/Pages/Auth/Login.vue`) memakai `resources/js/Components/FloatingConfigurator.vue`. Tombol palette di sana memakai `v-styleclass="{ ... enterActiveClass: 'animate-scalein', leaveActiveClass: 'animate-fadeout', ... }"`. Kelas `.animate-scalein` dan `.animate-fadeout` TIDAK didefinisikan di mana pun

  > **KOREKSI (review iterasi 1, informational):** diagnosa di atas keliru. Kode lama sebenarnya memakai `animate-fadein` yang **terdefinisi** di `app.css`, sehingga `animationend` tetap fire. Penyebab asli: `@next` menunjuk ke **wrapper `hidden` berlapis** di sekitar `<AppConfigurator>` (yang root-nya sudah `config-panel hidden`), jadi toggle `hidden` pada wrapper luar tak pernah memperlihatkan panel. Fix nyata = arahkan `@next` langsung ke root `<AppConfigurator>` (sudah diterapkan). Perilaku akhir benar. (dicek: hanya `.animate-slidedown` + `@keyframes fadein`/`slidedown` yang ada di `resources/css/app.css` ~baris 494–511). Direktif PrimeVue StyleClass (ter-autoregistrasi via `@primevue/auto-import-resolver` di `vite.config.js`) menunggu event `animationend` ketika `enterActiveClass`/`leaveActiveClass` diset; karena tak ada animasi CSS, `animationend` tak pernah fire → state transisi tersangkut → klik ulang tidak menutup. Topbar (`AppTopbar.vue`) BEKERJA karena memakai hanya `leaveToClass: 'hidden'` (tanpa `leaveActiveClass`) + `enterActiveClass: 'animate-slidedown'` yang terdefinisi. **Keputusan:** samakan FloatingConfigurator dengan pola topbar yang terbukti bekerja (buang `animate-scalein`/`animate-fadeout`, pakai `animate-slidedown` untuk enter, `leaveToClass: 'hidden'` tanpa leaveActive). `hideOnOutsideClick: true` sudah ada → klik-luar menutup.
- **Branding "Remunisasi" (DIKONFIRMASI, situs user-facing):**
  - `resources/js/layout/AppTopbar.vue` baris ~41: `<span>Remunisasi</span>` (brand topbar).
  - `resources/js/Pages/Auth/Login.vue` baris ~39: `<span ...>Remunisasi</span>` (brand panel kiri) + heading panel kiri baris ~47 "Sistem Remunerasi Pegawai RSUD Bangil" (ini deskripsi domain remunerasi, BUKAN nama app — biarkan, lihat Perubahan 6).
  - `resources/views/app.blade.php` baris ~9: `<title inertia>{{ config('app.name', 'Sakai Laravel') }}</title>` (fallback title).
  - `resources/js/app.js` baris ~15: `const appName = import.meta.env.VITE_APP_NAME || 'Sakai Laravel'` → dipakai `createInertiaApp.title`.
  - `config/app.php` baris ~16: `'name' => env('APP_NAME', 'Laravel')`.
  - `.env.example` baris 1: `APP_NAME=Laravel`; `.env` baris 1: `APP_NAME=Remunisasi_v2` (developer update manual, JANGAN commit `.env`).
  - `AppFooter.vue` TIDAK memuat nama "Remunisasi" (hanya kredit SIMRS/RSUD Bangil) → tidak perlu diubah untuk rename, kecuali ingin menambah nama app (opsional, lihat Perubahan 6).
  - JANGAN ubah: `config/sikep.php`, `config/twofactor.php` (issuer "Remunisasi RSUD Bangil"), `config/database.php`/`cache.php`/`session.php` (slug APP_NAME), nama folder, composer, DB, namespace, route — di luar scope.
- **Baseline test DIKONFIRMASI:** `php artisan test` → **160 passed (606 assertions)**. Jangan sampai turun.

- [ ] 4. Fix bug toast gagal upload yang tidak muncul pada kegagalan identik beruntun (Perubahan 4).
      **Pendekatan terpilih (paling bersih, konsisten dengan cara flash dibagikan): tambahkan nonce per-request pada payload flash di middleware, lalu watch nilai yang selalu berubah di layout watcher.** Di `HandleInertiaRequests::share()` key `flash`, tambahkan `'id' => (string) Str::uuid()` (atau `uniqid('', true)`/`microtime(true)`) yang dievaluasi tiap request (bukan closure yang menunda — nilai baru tiap kunjungan). Lalu di `TaskList.vue` ubah kedua watcher agar memantau `() => page.props.flash?.id` (atau watch objek flash dengan `{ deep: true }`) dan di dalam handler baca `page.props.flash.error`/`.success` lalu tampilkan toast bila ada. Dengan `id` berubah tiap request, dua error identik tetap memicu watcher → toast selalu muncul. **Pertahankan invariant recent fix:** gagal = satu toast error, sukses = satu toast sukses; jangan pakai `immediate: true` (hindari toast basi dari kunjungan sebelumnya); jangan tambah toast via `onSuccess` di TaskList (agar `back()->with('error')` yang 302→200 tidak memunculkan dua toast). Jika pakai nonce `id`: satu watcher pada `flash.id` yang mengecek error lalu success sudah cukup, atau pertahankan dua watcher tetapi jadikan `flash.id` sebagai sumber perubahan.
      Files: `app/Http/Middleware/HandleInertiaRequests.php` (tambah `use Illuminate\Support\Str;` bila pakai uuid; tambah `'id'` ke array `flash`), `resources/js/Pages/Katimker/TaskList.vue` (ubah target watcher). (Opsional selaraskan: tempat lain yang watch `flash.error` seperti `ReviewDetail.vue` baris ~71 — tidak wajib untuk bug ini, tapi jika ingin konsisten, pointkan juga ke `flash.id`.)
      Verify: `php artisan test` tetap 160 passed (flash `id` tidak dites unit, tapi pastikan tidak memecah test yang membaca `session('errors')`/flash). `npm run build` sukses. Runtime (manual): ajukan tugas tanpa selfie dua kali beruntun → toast error muncul DUA kali; satu kegagalan = satu toast; satu sukses = satu toast sukses (tanpa double-toast).

## Catatan & asumsi
- Tidak ada perubahan skema DB diperlukan: `tipe`/`mime` sudah ada; migrasi lokal tidak relevan untuk keenam perubahan ini (pesan user "migrasi juga di localhost" berasal dari task sebelumnya dan tidak menghasilkan migrasi baru di scope ini).
- Semua komponen UI diambil dari PrimeVue global (`Dialog`/`Image`/`Button`/`Tag`/`Chip`) — jangan import manual, jangan buat komponen baru dari nol.
- Pesan oversize (5 MB selfie / 10 MB bukti) dan pola single-toast adalah hasil fix sebelumnya; jaga agar tidak regresi (lihat `tests/Feature/KatimkerTaskTest.php`).
- Perubahan 5 bergantung pada perilaku runtime direktif StyleClass; jika hasil runtime berbeda dari root cause di atas, coder WAJIB verifikasi di browser dan perbaiki sampai perilaku "klik-ulang menutup" tercapai — tidak boleh di-skip sebagai "sudah bekerja".
